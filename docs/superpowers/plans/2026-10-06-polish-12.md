> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 사용자 요청 12건(순위표, 모바일 규칙, 해변 차례색, 모바일 진행 기록, 타이머 다시 채우기, 게임 종료 연출, 방 만들기 창, 로비 목록, 대기실 말풍선, 준비·시작 버튼, 커서, 진행 요약 창)을 반영한다.

**Architecture:**
- 백엔드는 타이머 다시 채우기 규칙 하나만 바꾼다(`PaperSafariSession`/`TurnStage`).
- 나머지는 프론트 React 컴포넌트와 `index.css` 변경이다.
- 게임 종료 연출은 `PaperSafariTable`에서 ROUND_OVER를 처음 받을 때 결과 창 표시를 늦추는 작은 상태 기계로 만든다.

**Tech Stack:** Java 21 / Spring Boot 3.5, React 19 + TS 5.9 + Tailwind 4 + motion 14, Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-10-06-polish-12-design.md`

## Review Focus

1. **타이머:** 가져오기 → 되돌리기 → 가져오기를 반복해도 마감이 늘어나면 안 된다(Task 1 테스트로 고정).
2. **게임 종료 연출:** 새로고침이나 늦게 들어온 사람에게는 연출 없이 결과 창이 바로 떠야 한다. 연출이 두 번 재생되면 안 된다(Task 6 테스트).

**Rule (spec §5):**
- 행동 뒤 단계나 차례가 바뀌면 마감을 15초로 다시 잡는다. 여기에는 DRAW→PLACE(가져오기)가 포함된다.
- 예외 1: CANCEL_DRAW(PLACE→DRAW 되돌리기)는 마감을 유지한다.
- 예외 2: 같은 차례에서 되돌리기가 한 번이라도 있었으면, 그 뒤의 가져오기(DRAW→PLACE)도 마감을 유지한다.
- "차례"는 (round, player)이고, 차례가 바뀌면 되돌림 표시가 사라진다.
- 시작 뒤집기, 엿보기, 놓기/버리기로 차례가 넘어가는 경우, 게임 종료는 지금처럼 다시 잡는다.
