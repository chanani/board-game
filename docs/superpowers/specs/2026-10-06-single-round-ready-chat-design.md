## 2. 백엔드

CLAUDE.md 객체지향 생활 체조(들여쓰기 1단계, `else` 금지, VO, 한 줄 점 하나(스트림 체이닝 예외), 일급 컬렉션, 필드 3개 이하, `BusinessException(ErrorCode)`, 통일 오류 응답)를 지킨다.

### 2.1 단판 규칙(#1)

- `papersafari` 엔진에서 토큰(`Tokens`, `TokenCount`, 관련 뷰 필드)과 라운드 간 준비(READY 액션, `readyVotes`)를 제거한다.
- 라운드가 끝나는 순간(`finishRound`) 게임 상태를 `GAME_OVER`로 만든다. 결과:
  - 최저점 단독 → `winnerId` = 그 사람, 결과 WIN, 나머지 LOSE.
  - 최저점 동점 → `winnerId = null`, 전원 DRAW.
  - 기권으로 1명만 남으면 그 사람 WIN(기존 sole survivor 규칙 유지), 기권자는 LOSE.
- 뷰(`PaperSafariView`): `tokens` 제거, `status`는 `IN_ROUND | GAME_OVER`, `lastRoundResult`(점수·결과)는 유지(결과 화면용), `roundNumber`는 항상 1(필드는 유지해 프론트 호환).
- `PaperSafariSessionView.readyPlayerIds` 제거.
- 이벤트·전적: 게임 종료 시 `RoundCompleted`(점수 기록, 평균 점수용)와 `GameCompleted`(승·무·패)를 함께 낸다. 전적 저장 구조는 바꾸지 않는다. 기권으로 끝난 게임은 라운드 기록 없이 게임 결과만(기존과 동일).
- 액션 `READY` 제거. 남은 액션: `FLIP, DRAW_DECK, DRAW_DISCARD, SWAP, DISCARD, PEEK, CANCEL_DRAW`.

### 2.2 되돌리기(#14)

- 액션 `CANCEL_DRAW`: 현재 차례 플레이어, 단계 `PLACE`, 손에 든 카드의 출처가 `DISCARD`일 때만. 카드를 버린 카드 더미 맨 위로 되돌리고 단계를 `DRAW`로. 손 카드는 비운다. 차례는 그대로.
- 출처가 `DECK`이면 409 `CANNOT_CANCEL_DRAW`("덱에서 뽑은 카드는 되돌릴 수 없어요."). 그 밖의 단계·차례 위반은 기존 오류(`INVALID_PHASE`, `NOT_YOUR_TURN`).

### 2.3 준비 → 시작(#11)

- 방 도메인에 준비 상태를 둔다: `ReadyMembers`(일급 컬렉션, 회원 ID 집합)를 `RoomMembers`의 두 번째 필드로 둔다(`RoomMembers(members, ready)`). 참가자가 빠지면 준비 집합에서도 빠진다.
- `POST /api/rooms/{code}/ready` body `{ "ready": true|false }` → `RoomResponse`. 참가자만(관전자·외부인 `NOT_IN_ROOM`), 대기 중일 때만(`ROOM_ALREADY_PLAYING`). 방장은 준비가 필요 없으며 방장이 보내면 400 `INVALID_INPUT`.
- 시작 조건: 인원 ≥ 최소 인원, 방장 외 전원 준비. 아니면 409 `PLAYERS_NOT_READY`("모두 준비해야 시작할 수 있어요.").
- 준비 초기화: 게임 시작 시, 게임 종료(대기 상태 복귀) 시 전원 준비 해제. 새로 들어온 참가자(참가·자리 앉기·자동 참가)는 준비 전. 방장이 나가 방장이 바뀌면 새 방장의 준비 표시는 의미가 없으므로 해제.
- `RoomMemberResponse`에 `ready: boolean` 추가(방장은 항상 false로 내려도 되며 화면은 방장 배지를 우선).

### 2.4 관전자 자동 참가(#5)

- 게임이 끝나 방이 대기 상태가 되는 시점(마지막 행동 처리·기권 처리 후 상태가 바뀔 때)에 `Spectators`를 들어온 순서대로 참가자로 옮긴다(정원까지). 남은 관전자는 관전자로 남는다.
- 기존 `POST /seat`는 유지(대기 중 관전자가 남아 있을 때 직접 앉기).
- 자동 참가 후 방 브로드캐스트에 반영되고, 레지스트리 색인은 그대로(같은 방).

### 2.5 채팅(#2)

- `ChatMessage(id: long 증가, memberId, nickname, text, sentAt)` — 필드 수 규칙에 맞게 `ChatAuthor(memberId, nickname)`, `ChatText`(VO: strip 후 1~200자, 위반 `INVALID_CHAT_MESSAGE` 400 "메시지는 1~200자로 입력해 주세요."), `sentAt`로 묶는다.
- `ChatLog`(일급 컬렉션): 최근 100개 유지.
- `ChatRegistry`: `RoomCode → ChatLog`. 방이 레지스트리에서 사라질 때 함께 삭제(`RoomRegistry` 삭제 시점에 이벤트 또는 직접 호출).
- 속도 제한: 회원별 최근 1초 안에 3개 초과면 `CHAT_TOO_FAST`(429, "메시지를 너무 빨리 보내고 있어요."), 개인 오류 큐로 전달.
- STOMP: `@MessageMapping("/rooms/{code}/chat")` body `{text}` → 그 방 사람(참가자·관전자)만, 저장 후 `/topic/rooms/{code}/chat`로 메시지 브로드캐스트. 실패는 기존처럼 `/user/queue/errors`.
- REST: `GET /api/rooms/{code}/chat` → 최근 100개(오래된 것부터), 그 방 사람만(`NOT_IN_ROOM`).
- `RoomTopicGuard`: `/topic/rooms/{CODE}`와 `/topic/rooms/{CODE}/chat` 두 경로를 허용 패턴으로(정확 일치 정규식), 둘 다 그 방 사람만.

### 2.6 오류 코드 추가

| 코드 | 상태 | 메시지 |
|---|---|---|
| PLAYERS_NOT_READY | 409 | 모두 준비해야 시작할 수 있어요. |
| CANNOT_CANCEL_DRAW | 409 | 덱에서 뽑은 카드는 되돌릴 수 없어요. |
| INVALID_CHAT_MESSAGE | 400 | 메시지는 1~200자로 입력해 주세요. |
| CHAT_TOO_FAST | 429 | 메시지를 너무 빨리 보내고 있어요. |

`ROUND_NOT_OVER` 등 토큰·라운드 준비 관련 코드는 쓰이지 않으면 제거한다.

## 3. 프론트엔드

### 3.1 규칙·전적 문구(#1)

- `rules.ts`(슬라이드 7장 + 요약), README: 토큰·3토큰 승리·다음 라운드 문구 제거. 마지막 슬라이드 = "누군가 6장을 모두 공개하면 즉시 끝나요. 남은 카드를 공개해 합이 가장 낮은 사람이 1승, 최저점이 동점이면 무승부예요."
- 게임 화면에서 토큰 표시(판 이름표 옆 금화) 제거, HUD "N라운드" 칩 제거(또는 "페이퍼 사파리"로).
- 전적(로비 요약·전적 페이지): 라운드 n판·라운드 승률 행 제거, 게임·승무패·승률·평균 점수 유지. 최근 경기 목록의 토큰 표시 제거.

### 3.2 대기실(#10 A안, #11)

- 바깥: 방 머리글(이름, "페이퍼 사파리 · 대기 중 · n/max명 · 👀 n", 나가기) 아래 2열(PC: 테이블 1.5 : 사이드 1, 모바일: 1열).
- 테이블: 원형 펠트에 정원만큼 의자를 원 둘레에 배치(2~5명 위치 표). 의자 = 이니셜 원판 + 연결 점 + 이름표 + 상태 칩(👑 방장 / ✔ 준비 완료(초록) / 준비 전(노랑)) + 조건부 내보내기. 빈자리는 점선 원 + "빈자리".
- 테이블 가운데: 방장은 "게임 시작"(조건 미충족이면 비활성 + 이유 문구: "2명 이상 모여야 해요" / "모두 준비하면 시작할 수 있어요"), 참가자는 "준비하기"/"준비 취소", 관전자는 "👀 관전 중 · 게임이 끝나면 자동으로 참가해요"(대기 중 관전자에게는 "자리에 앉기"). 그 아래 방 코드 복사 칩.
- 사이드: 위 채팅 패널(높이 고정, 내부 스크롤), 아래 규칙 요약.
- 간격: 패널 사이 24px, 펠트 테두리(13px) 고려한 여백 유지.

### 3.3 채팅(#2)

- `useRoomChat(code)`: 입장 시 `GET /chat`으로 기록, `/topic/rooms/{code}/chat` 구독(REST 입장 이후에만 — 방 채널과 같은 시점), `send(text)`.
- `ChatPanel`: 메시지 목록(내 메시지는 오른쪽 정렬·겨자색 말풍선, 남의 메시지는 닉네임 + 크림 말풍선), 새 메시지 오면 맨 아래로 자동 스크롤(사용자가 위로 올려 보고 있으면 유지), 입력창(최대 200자, Enter 전송, 빈 문자열 전송 불가), 오류 토스트.
- 게임 중: PC는 오른쪽 아래 💬 버튼 → 오른쪽 서랍(폭 320px), 모바일은 💬 버튼 → 하단 시트(높이 60vh). 닫혀 있을 때 새 메시지 수 배지. 돌아가기 바·토스트와 겹치지 않게 위치.

### 3.4 게임 화면(#3, #4, #12, #14, #16, #17)

- #3 모바일 상대 판 가운데: 상대 `Seat`의 손 칸을 레이아웃 흐름에서 빼고(판 오른쪽 위에 절대 위치로 겹쳐 띄움, 크기 유지) 판 자체를 가운데 정렬. 카드 비행 기준 영역(`hand:<id>`)은 유지.
- #4 모바일 상대 줄 간격 3px(`gap-[3px]`), 판 안쪽 여백 축소.
- #12 내 차례면 내 판(PlayerBoard 바깥 테두리)에 겨자색 `ring` + 빛나는 애니메이션(동작 줄이기면 고정 테두리).
- #14 버린 카드 더미에서 가져온 카드를 들고 있으면 "되돌리기" 아이콘 버튼(`UndoIcon`, aria-label "되돌리기") → `CANCEL_DRAW` 전송. 위치: 모바일은 오른쪽 칸(버리기 위), PC는 버리기 옆.
- #17 모바일: 내 손 카드(`hand:<me>`)를 오른쪽 칸의 **버리기와 예상 점수 사이**에 둔다(내 판 옆 손 칸 제거). 비행 애니메이션 도착점도 자동으로 그곳이 된다(영역 키 동일).
- #16 나가기: 게임 중(참가자)이면 확인 `Modal`: 문 아이콘 + "정말 나갈까요?" + [취소] [나가기]. "기권 처리" 문구 없음. 대기 중·관전자는 바로 나감.

### 3.5 결과 창(#1, #15)

- 게임 종료 화면 하나로 통합(라운드 결과 모달 제거): 카드 순차 공개 → 점수 → 승자(🏆 "○○님 승리!") 또는 "무승부예요".
- 하단: 참가자는 둥근 "다음 게임 준비" 버튼(누르면 `ready: true` 요청 후 모달 닫힘 → 대기실), 관전자·방장은 "대기실로" 버튼. 옆에 준비한 사람 이름 칩(둥근 테두리, 준비 완료면 초록 테두리 + ✔).
- 기존 "결과 모달 한 번만" 기억(dismissals)은 유지.

### 3.6 모달 공통(#6, #13)

- `Modal`에 닫기 버튼(✕ `CloseIcon`, aria-label "닫기")을 오른쪽 위에 표시(닫을 수 있는 모달만), 배경 클릭 시 닫힘(닫을 수 있는 모달만; 모달 안쪽 클릭은 무시).
- 규칙 슬라이드의 텍스트 "닫기" 버튼은 아이콘 버튼으로 대체.
- 상대 판 확대(#13): 판과 "예상 점수" 사이 간격 24px 이상.

### 3.7 로비(#7, #8, #9)

- #8 "기다리는 방" 섹션 머리에 "＋ 방 만들기" 버튼 → `CreateRoomModal`(방 이름, 최대 인원, 비공개 토글, 비밀번호). 기존 상시 폼 제거. 방 코드 입장은 상단 작은 패널로 유지.
- #7 비공개방: 체크박스 → 토글 스위치(`role="switch"`, `aria-checked`, 자물쇠 아이콘 + "비공개방"), 켜면 비밀번호 입력 등장.
- #9 방 코드 입력칸과 입장 버튼을 한 줄(입력 오른쪽에 버튼 붙임).

## 4. 테스트

백엔드:
- 엔진: 라운드 종료 = 게임 종료, 단독 최저점 WIN/LOSE, 동점 DRAW, 기권 sole survivor, 토큰·READY 없음, `CANCEL_DRAW`(더미 출처 성공·덱 출처 거부·단계/차례 위반).
- 방: 준비 토글(참가자만, 방장 거부, 게임 중 거부), 시작 조건(`PLAYERS_NOT_READY`), 시작·종료 시 준비 초기화, 종료 시 관전자 자동 참가(순서·정원), 새 참가자 준비 전.
- 채팅: `ChatText` 길이, `ChatLog` 100개 유지, 속도 제한, REST 기록 조회 권한, STOMP 전송·수신, 외부인 구독 거부, 방 삭제 시 기록 삭제.
- 전적: 단판 종료 시 게임 결과·라운드 점수 기록, 동점 무승부 기록.

프론트:
- 규칙 문구(토큰 없음), 전적 요약 행.
- 대기실: 의자·상태 칩, 방장 시작 비활성 이유, 준비 토글 요청, 관전자 문구.
- 채팅: 기록 로드, 수신 추가, 전송, 빈 문자열 차단, 200자 제한, 서랍·시트 열기와 배지.
- 게임: 1:1 모바일 상대 판 가운데 정렬 클래스, 줄 간격 3px, 내 차례 테두리, 되돌리기 버튼(더미 출처에서만), 모바일 손 카드 위치, 나가기 확인 모달(취소·나가기).
- 결과: 단판 결과(승자·무승부), 다음 게임 준비 요청, 준비 칩.
